# @fakturky/pdf

Server-side invoice PDF rendering with `@react-pdf/renderer`.

```ts
import { renderInvoicePdf, InvoiceDocument } from '@fakturky/pdf'
import { BRAND } from '@fakturky/core/brand'

const bytes = await renderInvoicePdf({
  ...documentForExport,
  language: 'cs',
  brandName: BRAND.name,
})
```

- Input: `InvoicePdfInput` = `DocumentForExport` from `@fakturky/domain` + `language`, `brandName`, optional
  `logo` / `signature` (PNG/JPEG bytes), texts and `showBrand`.
- Layout follows `docs/DESIGN.md` ("The invoice document"): white A4, hairline rules, Fraunces number and total,
  grayscale-safe. Title by type + VAT status, VAT recap per rate, CZK equivalents for foreign currency, legal
  texts for reverse charge / exempt, QR Platba (CZK) or EPC QR (EUR), repeated table header, `Strana X / Y`.
- Labels for `cs`, `sk`, `en` live in `src/i18n.ts`.
- Fonts (`fonts/`, SIL OFL): Inter 400/500/600 and Fraunces 500/600 (static instances, opsz 72, latin-ext).
- `examples/*.pdf|png` are regenerated by `pnpm --filter @fakturky/pdf test`.

## react-pdf gotchas handled here

- Fonts are re-registered for every render and renders are serialised: react-pdf reuses the fontkit subset
  between documents and corrupts glyph maps of every later document otherwise.
- No `lineHeight` on `Page`/`Text`: it makes `render` (page number) texts vanish.
